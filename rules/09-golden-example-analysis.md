# 09 — Golden Example Analysis

These two files are the primary golden examples for this Project.

They are **quality references**, not sources of facts. Never copy entity names, company-specific information,
figures, dates, accounting conclusions, or model assumptions from them into an unrelated artifact.

Written Project rules override the examples.

---

# A. Golden DOCX — Accounting Manual

**File:** `source-data/golden-examples/Golden - Accounting Manual.docx`

## Intended use

Use this as the primary visual and structural reference for:
- accounting manuals,
- policy manuals,
- formal internal/external accounting reports,
- long-form professional finance documents,
- documents with substantial tables and section hierarchy.

## Strong features to imitate

### 1. First-page hierarchy
The document uses a deliberate formal cover:
- company branding at the top,
- large document title,
- concise descriptive subtitle,
- intended audience,
- reporting date,
- restrained whitespace.

Use the same principle when a cover page is appropriate. Do not copy the company logo or branding into unrelated files.

### 2. Navigation
The manual uses a formal Table of Contents with:
- major sections,
- numbered subsections,
- page references,
- visual distinction between primary and secondary levels.

Long documents should have equivalent navigational clarity.

### 3. Page header
Interior pages use:
- a small brand mark / identifier,
- a thin horizontal rule,
- consistent positioning.

The principle to imitate is a restrained corporate header, not the specific Avondale logo.

### 4. Section hierarchy
The manual clearly distinguishes:
- Part label,
- Section label,
- main section heading,
- subsection heading,
- body text.

This is one of the primary DOCX hierarchy references for this Project.

### 5. Visual language
The manual uses a restrained corporate palette:
- dark navy as the main structural color,
- green as a secondary accent,
- neutral black/dark grey body text,
- pale blue/grey table shading.

Use this visual logic for formal manuals unless a current template or user request specifies a different palette.

### 6. Tables
Tables use:
- strong dark header rows,
- white header text,
- light alternating row fills,
- clear column hierarchy,
- compact cell padding,
- readable text density.

Tables should look integrated into the document rather than pasted from a spreadsheet.

### 7. Information density
The manual is information-dense without looking like a presentation deck.
It uses:
- compact body text,
- short spacing between related sections,
- full-page use,
- limited decorative elements.

This is the preferred balance for technical accounting and finance documents.

### 8. Lists
Lists use true Word bullet formatting, consistent indentation, and restrained spacing.

### 9. Footer
Page numbering is unobtrusive and consistent.

---

## Do not copy blindly

Do not automatically reproduce:
- the Avondale logo,
- Avondale names,
- Henderson Partners references,
- specific dates,
- specific accounting content,
- specific table data,
- exact cover-page wording.

The Project's Arial requirement remains controlling where applicable even if the reference file uses a different inherited theme font.

# B. Golden XLSX — Three Statement Financial Model

**File:** `source-data/golden-examples/Golden - Three Statement Financial Model.xlsx`

## Intended use

Use this as the primary golden reference for:
- three-statement financial models,
- DCF models,
- LBO models,
- debt schedules,
- valuation analyses,
- corporate-finance models,
- investment-banking-style schedules.

It is **not** the default style for general accounting registers, transaction logs, or simple trackers.

## Workbook architecture to imitate

The workbook uses a logical finance-model sequence that includes:
- cover page,
- assumptions,
- income statement,
- balance sheet,
- cash flow statement,
- PPE schedule,
- debt schedule,
- DCF,
- LBO analysis,
- FCFE valuation,
- PE returns analysis,
- WACC calculation,
- football-field analysis,
- charts.

Use the principle of logical flow from assumptions to statements to supporting schedules to valuation/output analysis.

## Strong formatting features to imitate

### 1. Section bars
Major model sections use strong filled bars with:
- white bold text,
- clear left alignment,
- consistent horizontal span.

For financial models, the example's red section bars are an acceptable preferred style.
If another approved template uses dark navy instead, preserve that template.

### 2. Assumption cells
Inputs are visually obvious through yellow highlighting.

Use yellow highlighting selectively for:
- scenario selectors,
- explicit assumptions,
- user-changeable driver cells,
- key valuation assumptions.

Do not turn entire models yellow.

### 3. Historical and forecast periods
Period headers are clearly differentiated:
- historical years marked with `A`,
- forecast years marked with `E`,
- units shown directly in the schedule heading.

Follow this convention where it improves understanding.

### 4. Numeric layout
The model uses:
- right-aligned periods and numeric data,
- left-aligned row labels,
- indented or italicized supporting metrics,
- blank rows to separate logical blocks,
- consistent decimal precision.

### 5. Financial number formatting
The example demonstrates:
- negatives in parentheses,
- zeros or nil balances displayed as dashes,
- percentages shown consistently,
- valuation multiples shown with `x`,
- units included in headers.

These conventions should generally be preserved in financial models.

### 6. Totals and subtotals
Key totals use:
- bold text,
- horizontal rules,
- grey emphasis bands where useful,
- stronger formatting only at decision-relevant outputs.

Avoid full cell boxing.

### 7. Balance-sheet checks
The balance sheet includes an explicit check line.
Important models should have visible integrity checks instead of hidden checks or hardcoded PASS labels.

### 8. Debt schedules
The debt sections clearly show:
- opening balances,
- additions,
- repayments,
- closing balances,
- interest rates,
- interest expense.

Use this roll-forward structure for financing schedules.

### 9. DCF layout
The DCF demonstrates a clean separation between:
- forecast operating cash flows,
- discount factors,
- discounted cash flows,
- WACC/PGR assumptions,
- terminal value,
- EV-to-equity bridge,
- valuation multiple output.

### 10. LBO layout
The LBO section demonstrates:
- entry assumptions,
- leverage structure,
- debt tranches,
- cash available for repayment/equity,
- separate debt roll-forwards,
- repayment timing.

### 11. Visual restraint
Despite strong header/input colors, most calculation cells remain white.
The model relies on spacing, alignment, formulas, and subtotal rules rather than heavy cell borders.

---

## Do not copy blindly

Do not automatically copy:
- company name (`Juice Co.`),
- historical data,
- assumptions,
- valuation conclusions,
- exact time periods,
- exact red/yellow colors into non-financial workbooks,
- model logic that does not fit the requested transaction.

The reference defines the **presentation standard and modeling discipline**, not a required model structure for every workbook.

# C. How to choose between the examples

## Use the DOCX golden example when:
- the user asks for a manual,
- the user asks for a report,
- the document is technical and long-form,
- the document contains repeated tables and numbered sections.

## Use the XLSX golden example when:
- the user asks for a financial model,
- the workbook contains historical/forecast periods,
- the workbook contains debt, DCF, LBO, valuation, or financial-statement schedules.

## Use neither style mechanically when:
- the task is a simple tracker,
- the artifact is a short letter,
- the user gives a more specific template,
- the existing source file has a deliberate style that should be preserved.
